# Reviewed API contracts for preserved mod-owned logic

Review baseline: Minecraft **1.16.5 / Forge 36.2.42** to Minecraft **1.20.1 /
Forge 47.4.23**, Java 17 target. This is a finite experimental profile, separate
from `simple-content-v1`. It does not turn structural mapping coverage into a
claim that arbitrary mod behavior is compatible.

`VerifiedLogicMappings` preserves original owned classes, methods, fields,
entrypoint construction, static initialization, instruction order, control flow,
exception handlers and supported lambda implementations. It produces exact rules,
not replacement application logic. The caller must perform source and target
linkage/bytecode validation and an all-or-nothing conversion. Execution is a
separate validation gate; this compiler never loads input classes.

## Actual declarations and namespace composition

The local reviewed development sources were generated by the pinned ForgeGradle
builds from their real Minecraft/Forge dependencies. They are development evidence,
not redistributed sources or product dependencies on a developer's cache:

| Source archive under the ForgeGradle `minecraft_user_repo/net/minecraftforge/forge` directory | SHA-256 |
|---|---|
| `1.16.5-36.2.42_mapped_official_1.16.5/forge-1.16.5-36.2.42_mapped_official_1.16.5-sources.jar` | `bbe2d148f96694271c43fc2ba584463d75d9ffc490abd0469ae66b831293d376` |
| `1.20.1-47.4.23_mapped_official_1.20.1/forge-1.20.1-47.4.23_mapped_official_1.20.1-sources.jar` | `4bd6656a7cbe3809da68f3b709ca0f2fa186575f58538668c58ce30cb38c4932` |

The declarations and access flags were additionally inspected in the corresponding
mapped API and `forge-<version>-srg.jar` binaries without initializing classes.
Mapping direction/provenance and portable-data permission gates remain as described
in [Mappings](MAPPINGS.md), [Portable mapping data](PORTABLE_MAPPING_DATA.md) and
[packaging rights](PACKAGING_RIGHTS.md). No old game/Forge binary is embedded by this
profile to simulate independence.

`LogicApiNamespace` joins each version's official-to-obfuscated and
obfuscated-to-SRG tables, including complete descriptors, then normalizes actual API
declarations. Source production uses MCP class owners and `func_*`/`field_*` members;
target production uses official class owners and `m_*`/`f_*` members. Target
`net/minecraft/src/C_*` placeholders are never emitted. Forge-added declarations
that inherit vanilla overrides are resolved through their actual trusted ancestry;
unmapped Forge members retain their declared names. Ambiguity, collisions and
missing required declarations fail closed.

Normalization is limited to directly referenced reviewed types and their complete
real superclass/interface ancestry, retaining all declarations within that closure
for override checks. Unrelated game APIs are not rewritten or consulted merely
because they coexist in the inventory. For example, the actual 1.16.5 official
table contains `WorldBorder.removeListener(BorderChangeListener)` (`cfu.b(cfs)`),
but the pinned source TSRG has no matching method row. This unrelated method is
not needed by the item profile and cannot invalidate its whole trusted inventory;
an attempted direct use would still be unsupported, and a missing row within the
required closure would still fail closed. Canonical and source MCP namespaces are
kept separate because a name such as `ItemRenderer` can refer to different classes
in the two namespaces.

The tables below document a small semantic allowlist, not a substitute manually
maintained version mapping. Exact names are derived again from supplied data and
checked against actual declarations on every compile. Generic generator candidates
stay `HIGH`; an independent named recipe, exact declaration/access/opcode proof and
the implemented descriptor operation are additionally required to produce a
`VERIFIED` rule. Review entries keep structural confidence, generated confidence,
generic candidate status, contract and adapter binding separate.

## Item behavior: externally observable foil predicate

| Contract | Source production symbol | Target production symbol |
|---|---|---|
| `logic.item-constructor.v1` | `net/minecraft/item/Item.<init>(Lnet/minecraft/item/Item$Properties;)V` | `net/minecraft/world/item/Item.<init>(Lnet/minecraft/world/item/Item$Properties;)V` |
| `logic.item-properties-constructor.v1` | `net/minecraft/item/Item$Properties.<init>()V` | `net/minecraft/world/item/Item$Properties.<init>()V` |
| `logic.item-stack-size-property.v1` | `Item$Properties.func_200917_a(I)Lnet/minecraft/item/Item$Properties;` | `Item$Properties.m_41487_(I)Lnet/minecraft/world/item/Item$Properties;` |
| `logic.item-foil-override.v1` | `Item.func_77636_d(Lnet/minecraft/item/ItemStack;)Z` | `Item.m_5812_(Lnet/minecraft/world/item/ItemStack;)Z` |
| `logic.item-stack-count.v1` | `ItemStack.func_190916_E()I` | `ItemStack.m_41613_()I` |

Both `Item.isFoil(ItemStack)` declarations are public, non-static and non-final;
the default implementation delegates to that stack's enchantment predicate. The
legacy source is `net/minecraft/item/Item.java:230`; the target source is
`net/minecraft/world/item/Item.java:284`. Native `ItemStack.hasFoil()` dispatches
through its item's predicate in both versions (respective source lines 760 and
804). An override of this predicate is therefore a small externally observable
native call path: the original owned predicate remains the executed implementation.
The mapped MCP-snapshot source calls this method `hasEffect`, while the
official-mapped development source calls it `isFoil`; production input is matched
by its actual SRG signature, not source spelling.

Constructors use `INVOKESPECIAL`; ordinary property, count and predicate calls use
`INVOKEVIRTUAL`. Explicit `super` invocation of the reviewed predicate may use
`INVOKESPECIAL`. Owned overrides and inherited owned-owner call references receive
the same exact target override name. Other external overrides, accidental target
overrides, changed final/static/public contracts and unresolved inherited methods
are refused.

Stack count remains integer stack count; this does not authorize arbitrary
`ItemStack` mutation or NBT/component migration. `Properties.stacksTo` is the same
builder-style stack-limit property, but this slice does not grant support for
durability, creative tabs or other property combinations. The no-argument
`Item.getMaxStackSize()` is public **final** in both reviewed versions, not a valid
subclass override candidate. Forge's legacy `IForgeItem.getItemStackLimit(ItemStack)`
and target `getMaxStackSize(ItemStack)` are distinct extension contracts and remain
outside this slice.

## Native registration retains the original entrypoint

| Operation and opcode | Exact legacy descriptor | Target change |
|---|---|---|
| `GETSTATIC ForgeRegistries.ITEMS` | `Lnet/minecraftforge/registries/IForgeRegistry;` | None; actual public static final field |
| `INVOKESTATIC DeferredRegister.create` | `(Lnet/minecraftforge/registries/IForgeRegistry;Ljava/lang/String;)Lnet/minecraftforge/registries/DeferredRegister;` | None |
| `INVOKEVIRTUAL DeferredRegister.register` | `(Ljava/lang/String;Ljava/util/function/Supplier;)Lnet/minecraftforge/fml/RegistryObject;` | Return owner becomes `net/minecraftforge/registries/RegistryObject` |
| `INVOKEVIRTUAL DeferredRegister.register` | `(Lnet/minecraftforge/eventbus/api/IEventBus;)V` | None |
| `INVOKESTATIC FMLJavaModLoadingContext.get` | `()Lnet/minecraftforge/fml/javafmlmod/FMLJavaModLoadingContext;` | None |
| `INVOKEVIRTUAL FMLJavaModLoadingContext.getModEventBus` | `()Lnet/minecraftforge/eventbus/api/IEventBus;` | None |

These contracts preserve the mod's own registration statements, namespace,
registry identifiers, deferred suppliers and mod event-bus attachment. There is no
generated replacement bootstrap graph or runtime registration shim. Both Forge
versions implement these operations natively.

Behavior difference: legacy `DeferredRegister.register(String,Supplier)` (source
lines 94–114) defers `sup.get().setRegistryName(key)`. Target registration (lines
175–195, dispatch around line 386) uses native registry ownership through
`RegisterEvent.register(registryKey,id,supplier)` and updates the registry object.
That identity-preserving native route is reviewed only for ordinary owned item
suppliers. Direct `IForgeRegistryEntry`, `setRegistryName`, `getRegistryName`, custom
registry factories or observation of obsolete registration internals is unsupported.

In particular, legacy `RegistryObject.get()` has erased return
`IForgeRegistryEntry` plus an `Object` bridge, whereas the target generic erasure
returns `Object`. This profile allows the reference type to be stored/remapped, but
**does not authorize either legacy `get` call**. The positive fixture does not make
such a call. A class relocation alone must not grant it compatibility.

Trusted API data must include the real event bus and FML declarations. The pinned
source userdev specifies `net.minecraftforge:eventbus:4.0.0`; the target common
installation supplies `6.2.33`, plus its separate
`javafmllanguage:1.20.1-47.4.23` JAR. Missing event bus/FML declarations produce an
actionable `LOGIC_MAPPING_DATA_REQUIRED` failure, never synthetic API classes.
Legacy `IForgeRegistryEntry` can appear in trusted read-only superclass metadata
while direct references from input mod code still remain unsupported.

## Owned Java logic and lambda boundary

Owned methods, fields, helper hierarchies and interfaces keep their names unless an
independently reviewed external override requires a rename. Debug signatures,
frames, annotations, exception tables, inherited member owners and implementation
handles are scanned as well as ordinary instructions. Purely owned method names
are not translated by a guessed global name map.

`@Mod(value=...)` is allowed only in actual class annotation attributes on a
concrete owned class. It is rejected on methods, fields, parameters and type-use
attributes: Forge's discovery metadata can observe those attributes too, so
trusting only Java source-level annotation targets would be insufficient.
`@FunctionalInterface` is allowed only on an actual owned interface class, with
no annotation values. Other annotation targets remain unsupported.

Finite direct JDK calls are `Object.<init>()`,
`IllegalArgumentException.<init>()` / `<init>(String)`, `Supplier.get()` and
`IntUnaryOperator.applyAsInt(int)`. Platform class resources supply Java 17
declarations without `Class.forName`, input class loading or initializer execution.
This declaration check plus the finite Java 8-era contract allowlist is not an
emulated Java 8 runtime and does not authorize other Java APIs, reflection or I/O.

Only standard `LambdaMetafactory.metafactory` with its exact three static
arguments, an owned implementation handle and verified capture/argument/return
shape is admitted. No `altMetafactory`, serialization, arbitrary bootstrap,
constant dynamic, free method handles or method-handle calls are supported.
`MethodHandles.Lookup`, `MethodType`, `MethodHandle` and `CallSite` are allowed only
as the verified bootstrap's metadata (plus javac's related `InnerClasses` metadata),
not as ordinary fields/signatures or directly invoked APIs.

The real original fixture's `LogicItem::new` has a no-argument
`H_NEWINVOKESPECIAL` constructor handle, a `Supplier` SAM returning `Object`, and
instantiated return `Item`. The implementation permits this **zero-capture,
zero-argument** form only for a concrete owned class whose exact source and target
ancestry proves it is an `Item`. The owned result may be returned directly or
upcast to that reviewed Item ancestor. No constructor-argument adaptation is
performed. Capturing/static integer lambdas retain exact primitive argument and
return contracts. The bytecode/linkage validator remains an additional gate and
may refuse a shape not implemented there even if this mapping compiler can describe
it.

Every generated rule is bound to the existing implemented offline operation
`logic.symbol-contracts.v1` / `PreservedLogicAdapter.remapDescriptor`. This operation
is actually called for class-component descriptor composition; it does not claim
to emulate arbitrary Forge calls or discard original application behavior.

## Explicit limits and evidence levels

No new support is claimed for entities, block entities, rendering, GUI hooks,
worldgen, dimensions, packets, capabilities, config, general events, mixins,
coremods, access transformers, arbitrary registries or optional integrations.
Unknown direct external types/members, annotations, custom opaque attributes,
native/synchronized methods, monitors and old `jsr`/`ret` bytecode fail closed.

The mapping unit fixtures prove finite acceptance/refusal and namespace/override
rule construction only. They are not counts of compatible real mods, do not run
the source mod, and do not establish game behavior. Source runtime probe, converted
runtime probe, client assets/UI and multiplayer observations must be recorded
separately by the integration validation, tied to exact artifact hashes. This
document does not assert that those later gates passed.
